# Code scan 2026-10-28 (capie + rename-anything, HOI4 1.19.4.0)

Read-only scan of code quality and stability. Nothing was edited, built, committed or published;
this report is the only file written.

**Scope.** The scan started on `port-1.19.4.0`. During the scan both repositories moved: capie
`main` now holds the merge `4262391` plus `ffc34c5`, `aef1592` and `4dba74c` (HEAD), and
rename-anything `main` holds the merge `6c56817`. Every finding below was re-checked against
those HEADs. Findings that HEAD already fixed are listed under [Resolved during the scan](#resolved-during-the-scan).

**Baseline.** Known items from `stability-plan-1.5.1.md` and `research/port-1.19.4.0.md` are not
repeated: N6 (noexcept hooks), N7-N11, the `+0xBF9`/`+0xE8` pins, the SetVariable vtable slot,
S7-S9, P1/P2/P4/P5. Neither repository contains a "readability plan" document with steps 4-12;
the readability items below may overlap with it.

**Binary checks.** Ghidra (REA) was used first, but `read_bytes` on `hoi4.exe` timed out after
1800 s because the analysis had not finished. The binary checks were then done with capstone on
the file itself. Its SHA-256 `B6650C85…D888` matches `game_build.hpp`. RVAs below are relative to
`0x140000000`.

**Severity.** *critical* means it blocks the release or can corrupt game state. *high* means a
likely regression or crash with no safety net. *medium* means a real defect with a narrow trigger,
or a test gap on a safety mechanism. *low* means hygiene.

**Effort.** S is up to 2 h, M is up to 1 day, L is more than 1 day.

Paths are relative to the repository named in each section.

## 1. Findings ranked by severity

### Critical

**C1 — `build.ps1` reads files that only exist in the old monorepo (capie)**
- **Where:**
  - `plugin/capie/build.ps1:312`: `sdk\capie-script-sdk\examples\capie_demo\interface\mydemo.gui` is passed to `public_editor_test`.
  - `build.ps1:322` → `tests/check_status_localisation.py:51`: `REPO/"mod"/"localisation"/…`.
  - `build.ps1:324` → `tests/check_alphabet.py:27,30`: `REPO/"sdk"/…/capie_charset.py` and `REPO/"tools"/"modgen"/"charset.py"`.
- **What is wrong:** none of `sdk/`, `mod/` or `tools/modgen/` exists in capie (verified with `ls`).
- **Failure:**
  - `demo_gui_tests` (`tests/public_editor_test.cpp:776`) fails `check(!text.empty(), "demo .gui readable")`.
  - The two Python checks crash with `FileNotFoundError`.
  - So `build.ps1` always fails. Release preflight runs exactly this script (`tools/release/release.toml:70-75`, "CAPIE native build and offline tests"), so the preflight can never pass in a clean clone. That pushes the maintainer towards skipping it.
- **Fix:** vendor the three inputs (demo `.gui`, status localisation subset, charset table) into `plugin/capie/tests/contract/` with a SHA-256 lock file and a `sync` script that copies them from rename-anything on demand. This is the minimal form of P1. Until then, report SKIPPED, not PASS, when the contract file is missing.
- **Effort:** M.

### High

**H1 — the fault latch has no test (capie)**
- **Where:** `plugin/capie/src/engine/game_calls.hpp:79-100` (`game_call_faulted`, `game_call_exception`, `game_calls_allowed`). No file under `plugin/capie/tests` mentions either symbol (grep), and no mutant in `tests/mutants.json` targets them.
- **Failure:** a refactor that drops `game_call_faulted.store(true)`, or the `!game_calls_allowed()` early returns, keeps every suite green. After one access violation inside `SetText`, CAPIE would keep calling the game into a half-unwound engine state (lock held, object half updated). That is exactly what N1 was meant to prevent.
- **Fix:** add a test whose fake `set_text` dereferences null. Then assert:
  1. the wrapper returns false;
  2. the next `guarded_find` and `guarded_refresh` return failure without calling their fakes;
  3. a fault in a CAPIE-side `ProcessMemory::read` does **not** set the latch.

  Add two mutants: remove the store, and remove one `game_calls_allowed()` check.
- **Effort:** S.

**H2 — the "root equal to parent" refusal (N10 part 1) has no test (capie)**
- **Where:** commit `d20d5c2` added the guard in three places:
  - `src/features/editor/window_view.hpp:95` (`parent == out.root`);
  - `src/features/focus/focus_release.hpp:194`;
  - `src/features/caption/caption_refresh.hpp:849-854`.

  It changed no test file.
- **Failure:** reverting any guard goes unnoticed. The editor would then prefill or apply into the **parent** window, which `Bind` returns when the window factory fails (Ghidra M1 in the port notes). That means writing text into another GUI's edit boxes.
- **Fix:** one fixture case per guard (root pointer == parent pointer, otherwise valid chain → `invalid`), plus three mutants.
- **Effort:** S.

**H3 — the core DLL's own game calls bypass SEH and the fault latch; the header claims otherwise (capie)**
- **Where:**
  - `src/engine/game_calls.hpp:5-9` says "CAPIE calls exactly six game functions … Each call runs under an SEH filter".
  - The core DLL also calls `PortraitEntryValid` (`src/features/country/portrait_layer_hooks.hpp:219`), `string_copy` (`portrait_layer_hooks.hpp:224` and `name_layer_hooks.hpp:289`), and the `UpdateNames` trampoline for every changed country (`name_layer_hooks.hpp:248`).
  - None of these is under `__try`, and none checks `game_calls_allowed()`.
  - `game_call_faulted` is an `inline` variable, so each DLL has its own copy; a latch set in `capie_editor.dll` never stops `capie_core.dll`.
- **Failure:** `PortraitEntryValid` dereferences the sprite-database global (`rva::sprite_database_global`). If `ResolvePortrait` runs during a load or teardown window where that database is being rebuilt, the access violation is not caught and the game crashes. The crash dump then points into CAPIE's hook.
- **Fix:**
  - Add `guarded_portrait_valid` and `guarded_string_copy` wrappers that, on a fault, latch, turn the portrait or faction layer off, and fall through to the original.
  - Export one latch (or a shared section) so both DLLs see it.
  - Correct the header comment so it covers the editor DLL only.
- **Effort:** S-M.

**H4 — the legacy benchmark step needs a build folder that does not exist (capie)**
- **Where:** `plugin/capie/build.ps1:332-337` adds `/I plugin\build\country-status-candidate\stage`. The folder is missing (`ls plugin/build` lists `capie-1.5.1`, `capie-1194*`, `capie-launcher`, `capie-proxy`, `capie-rc`, `release-verify`).
- **Failure:** `[build.rebuild_capie]` (`release.toml:87-90`) calls `build.ps1` **without** `-SkipBenchmarks`. Even after C1 is fixed, `release.py build --rebuild-capie` fails at `bench_country_legacy`.
- **Fix:** skip the legacy benchmarks with a notice when the folder is missing, or remove them; also pass `-SkipBenchmarks` in `rebuild_capie`.
- **Effort:** S.

**H5 — the only live proxy test still pins the 1.19.3.0 build (capie)**
- **Where:** `tools/test-proxy-loader.ps1:39-43` hard-codes the game hash `7DC947BE…3A031D5` and the old `capie_core`/`capie_editor` hashes. This is a third pin list next to `deploy/bundle-inputs.json` (B2).
- **Failure:** on 1.19.4.0 the script throws `Unsupported game executable.`, so the proxy path cannot be smoke-tested for 1.5.1.
- **Fix:** read the game hash from `src/core/game_build.hpp` and the DLL hashes through `Read-CapieBundleInput` (as `build_proxy.ps1` does).
- **Effort:** S.

**H6 — the release step does not re-verify what it uploads (capie)**
- **Where:** `tools/release/releasekit/github.py:140-183` (`check_local`) checks that the assets exist, the manifest version, and that the pin equals the manifest `zipSha256`. It never re-hashes the ZIP, never checks `SHA256SUMS.txt`, and never re-verifies the signature.
- **Failure:** `_package` writes the ZIP before the manifest (`package.py:884` then `:889`). If a re-run writes a new ZIP and then fails, the old manifest and signature sit next to the new ZIP, and `--publish` uploads the mismatch. Every `install.ps1` then refuses the release, after it is public.
- **Fix:**
  - In `check_local`: re-hash the ZIP against the manifest and the pins, and verify `SHA256SUMS.txt` and the `.sig`.
  - In `_package`: delete the stale manifest, `.sig` and sums before writing.
- **Effort:** S.

### Medium

**M1 — an own country Apply is dropped silently when the transport cannot be prepared (capie)**
- **Where:**
  - `src/dll/capie_editor.cpp:317-320`: `prepare_transport` or `still_current` fails → `bridge_rejected(…)` and `return`, with no stale sentinel.
  - The RN6 comment four lines above (`:308`) promises "never drop an own Apply silently".
  - `prepare_transport` fails, among others, when `country_ready()` is false (`src/features/editor/transport.hpp:397-400`).
- **Failure:** in launcher mode the editor and the core are initialised separately. If `capie_core` refuses (RTTI mismatch, pin drift), every country rename click does nothing and the player sees nothing. The only trace is CAPIE's log. In proxy mode the editor is skipped when the core fails (`proxy/loader.hpp:182-185`), so this path is launcher-only.
- **Fix:** route these failures through `dispatch_stale` with a new `StaleCode` (e.g. `core_inactive = 4`) and a localised explanation in the script.
- **Effort:** S.

**M2 — other mods' grammar-editor Applies are swallowed when CAPIE's chain check fails (capie)**
- **Where:** `src/features/editor/public_editor.hpp:825-828`. When `inspect_chain` returns `invalid`, the hook returns `true` and never calls the original Dispatch.
- **Failure:** after the next port, one wrong layout offset makes every grammar window "invalid", and every SDK mod's Apply button stops working, even for parts CAPIE does not own. This is fail-closed on someone else's feature.
- **Fix:** forward the click to the original with only `capie_cap`/`capie_ver` and an error epoch (e.g. `capie_epoch = -4`), and let the other mod's script decide.
- **Effort:** S.

**M3 — focus release treats unreadable flag bytes as "parent hidden" (capie)**
- **Where:** `src/features/focus/focus_release.hpp:200-205`:
  - `parent_visible = parent && rd(...) && shown_not_hidden(flags)`, so a failed read gives false;
  - the `root_flags`, `window_desired` and `window_parent_seen` reads ignore their result;
  - the function still returns `Kind::valid`.

  The caption inspection returns `invalid` for the same case (`caption_refresh.hpp:850-856`).
- **Failure:** a parent root that is being torn down (page decommitted) reads as hidden. That triggers `release()`, a real `FocusSwitch(manager, nullptr)` call into the game on a window in teardown.
- **Fix:** return `Kind::invalid` when any of the four reads fails, the same as the caption code.
- **Effort:** S.

**M4 — `guarded_find`'s null-object rejection is not tested independently (capie)**
- **Where:** `src/engine/game_calls.hpp:140-146`.
  - Edit callers also compare the definition name (`prefill.hpp:88`, `keylog.hpp:431`, `debug_observer.hpp:89`), so a mutant that deletes the vtable comparison survives.
  - The test fixture's null instant-text object has vtable 0 (`tests/public_editor_test.cpp:274-276`).
  - The literal `vt_null_edit = 0x2BC80B0` is not in `rtti_exe_test`.
- **Binary check:** `hoi4.exe` has distinct RTTI classes `.?AVCNullEditBox@@` (type descriptor `33D8148`) and `.?AVCNullInstantTextBox@@` (`33D81B0`). So the runtime check is sound; only the test is weak.
- **Fix:**
  - Add both null classes to `rtti_exe_test` (find their vtables through the COL).
  - Give the fixture's null instant object a non-zero vtable.
  - Add a mutant that removes the comparison, killed by an instant-text case.
- **Effort:** S.

**M5 — no negative tests for `bounded_map`; fixtures reuse source constants (capie)**
- **Where:** `src/engine/widgets.hpp:109-115`. No test covers a mask above the limit, a mask of `-1`, or an unreadable entry array.
- **Fixture problem:** `put_empty_maps` (`tests/public_editor_test.cpp:70-74`, and the same in both legacy editor suites) builds the fixture from `off::root_edit_map` etc. A wrong offset therefore moves the fixture with it.
- **Pin coverage:** `root_children 0x1508`, `map_mask 0x2C` and `map_entries 0x20` are not covered by any byte pin; `0x13F0` and `0x1380` are, inside the find signatures.
- **Failure:** a layout change in the next build is caught only in game.
- **Fix:** add the negative cases. Pin the `+0x1508` children access and the map field reads in `23319D0`, or add a static check that the signature bytes and the `off::` values agree.
- **Effort:** S-M.

**M6 — legacy editor suites still model 1.19.3.0 lookups (capie)**
- **Where:** `tests/legacy/editor_integration_test.cpp:108,121` and `tests/legacy/editor_inherited_test.cpp:137,143`. Their fake `FindEdit`/`FindInstantText` return `nullptr` on a miss; 1.19.4.0 returns a null object.
- **Failure:** the 24 mutants "killed" by these suites are killed against a game that no longer exists. The null-object path (the one that matters now) is exercised only by `public_editor_test`.
- **Fix:** return a typed null object, as `public_editor_test` does.
- **Effort:** S.

**M7 — `capie_core.dll` init has no test (capie)**
- **Where:** no test loads `capie_core.dll`. Untested:
  - the wrong-host refusal (code 10, `src/dll/capie_core.cpp:259-262`, which returns before any log line);
  - code 20;
  - turning the portrait layer off on an RTTI mismatch (`:277-283`);
  - the editor's RTTI refusal code 23 (`capie_editor.cpp:492`).

  Only the editor's code 10 is tested (`legacy/editor_inherited_test.cpp:403-409`).
- **Fix:** copy the editor's wrong-host test for the core DLL. Factor the gating (pins → RTTI → layer flags) into a pure function and table-test it.
- **Effort:** M.

**M8 — exe-dependent tests pass quietly when `hoi4.exe` is missing (capie)**
- **Where:** `plugin/capie/build.ps1:276` prints one line and passes no argument. The exe tests then do shape checks only (e.g. `tests/rtti_exe_test.cpp:153-156`), and `build.ps1:344` still prints "passed". Nothing checks that `-GameExe` matches `game_exe_sha256`.
- **Failure:** a release build on a machine without the game (or with a different build) is green with no pin or RTTI verification.
- **Fix:** add a `-RequireGameExe` switch (the release kit passes it) with a hash check, and print `SKIPPED (n exe checks)` in the final line.
- **Effort:** S.

**M9 — no mutants for the 1.19.4.0 safety code (capie)**
- **Where:** all 249 `find` strings in the three `mutants*.json` still match once, so the lists are not stale. But `game_calls.hpp` has one mutant, `window_view.hpp` one, and `widgets.hpp`, `rtti.hpp` and `build_identity.hpp` none.
- **Fix:** add mutants for H1, H2, M4 and M5, and for the RTTI name compare.
- **Effort:** S.

**M10 — four guarded reads of the same string on every SetVariable (capie, performance)**
- **Where:** `src/features/country/name_layer_hooks.hpp:201,207` and `src/dll/capie_core.cpp:156,160`. Each runs `string_equals` on `effect+0xC8`, which is a `VirtualQuery` plus a copy.
- **Failure:** `set_variable` is one of the most frequent effects, so every execution in a heavy mod pays about four syscalls during the day tick.
- **Fix:** copy the 32-byte `MsvcString` once, reject on size first (all four commit names are 12 bytes, stored inline), and dispatch from that copy.
- **Effort:** S.

**M11 — console bridge game calls are unguarded (capie, `-Console` developer build only)**
- **Where:** `src/features/console/console_bridge.hpp:281,369,410,415,431,477` call `add_or_replace`, the delegate, `tag_parse`, `country_of`, `sprite_find` and `assign` directly, with no `__try` and no fault latch. Only the memory reads use `ProcessMemory`.
- **Failure:** a stale console pin after a port turns a console command into a game crash.
- **Fix:** wrap the calls the same way as `engine::guarded_*`.
- **Effort:** M.

**M12 — the release kit's identity check accepts suffixed versions (capie)**
- **Where:** `tools/release/releasekit/package.py:98`, `TOKEN_CHARS = "0123456789.abcdefABCDEF"`. A hyphen is not in the set, so `1.5.1-dev` inside a binary matches `capie_release = 1.5.1` (B3).
- **Failure:** a debug or dev binary passes the B3 check.
- **Fix:** match the NUL-terminated C string (the form of `build_identity.hpp`) and add a `1.5.1-dev` test.
- **Effort:** S.

**M13 — a half-created GitHub release blocks every retry (capie)**
- **Where:** if `gh release create` fails after the release object exists (`github.py:344-347`), the next run stops at "release vX already exists" (`:206-208`) with no hint, and the release may already be visible.
- **Fix:** create the release as a draft, upload, check the asset list, then publish; on failure, print the cleanup command.
- **Effort:** M.

**M14 — `--rebuild-capie` overwrites the reviewed binaries; the binary folder is named in three places (capie)**
- **Overwrite:** `release.toml:87-90` builds straight into `plugin/build/capie-1.5.1`, the folder whose hashes are reviewed and pinned. MSVC output is not bit-reproducible, so the reviewed files are lost.
- **Three names for one folder:** it is named in `release.toml:83`, in each `source` of `deploy/bundle-inputs.json`, and hard-coded at `build_launcher.ps1:209` (`LICENSE.MinHook.txt`, not hashed). `package.py:437` checks `capie_output`, not the JSON `source`.
- **Fix:** build into a scratch folder and compare, and derive the folder from the JSON alone.
- **Effort:** S.

**M15 — the generator ignores `integrated_dlc/` (rename-anything)**
- **Where:** `tools/modgen/features/portraits.py:418-433` (`read_textures`), `:438-460` and `:483-509` scan only `root` and `dlc/*`; the same for `tools/modgen/features/char_portraits.py:117-123`. `tools/check.py:287` already accepts `integrated_dlc/*`, so the two tools disagree.
- **Why it matters:** the game has `integrated_dlc/dlc018_together_for_victory`, `dlc020_death_or_dishonor`, `dlc022_waking_the_tiger` and `dlc023_man_the_guns` (verified).
- **Failure (measured by the scan):**
  - 140 character portrait sprites are missing from the portrait catalog;
  - 210 base sprites whose texture lives only there are dropped (e.g. `GFX_NZL_elsie_farrelly`);
  - 185 characters get the "unknown" mini portrait (e.g. `AST_eric_campbell`).
- **Fix:** treat each `integrated_dlc/*` as a base root (pack 0, no `has_dlc`) in `read_textures` and in the `.gfx` scan. Check in game that integrated DLC needs no DLC gate.
- **Effort:** S-M.

**M16 — generator output depends on which DLC the maintainer owns (rename-anything)**
- **Where:** `tools/modgen/features/portraits.py:336,448,497`. The `gen.py` docstring promises byte-for-byte determinism "for the same game data", but Steam creates a `dlc/` folder only for owned DLC.
- **Failure:** a maintainer missing one DLC regenerates a different portrait catalog: pack numbers shift and the catalog fingerprint changes. After release, every player's stored picker indices read as stale.
- **Fix:** commit the expected DLC list, and fail the generator (or the equality test) when a folder is missing. Print the DLC set into the generated header.
- **Effort:** S.

**M17 — the generator equality test misses the mini portraits and skips on most setups (rename-anything, P3 still open)**

- **Fix:** pass `char_portraits.read(...)`, read the game path from an environment variable, and assert that no file with the GENERATED header under `mod/` was left unproduced.
- **Effort:** S.

**M18 — rename-anything's tests cannot run from a clean clone (monorepo leftovers)**

## 3. Checked and found sound (no finding)

- **BuildNameKey substitution scope.** `UpdateNames` (`75E660`) calls `BuildNameKey` (`734B60`) at six sites, all for the same country (`rdi`):
  - `75EA22`, `75EB19` and `75EBD5` pass the cosmetic tag `rdi+0x1488` (the first is the pinned site `75EA17`);
  - `75EC4C`, `75ECE9` and `75ED4B` are fallbacks when the name came back empty, and pass the country's own tag (or the `+0x130C` tag).

  So the unconditional substitution in `name_layer_hooks.hpp:176-185` cannot leak a rename into another country.
- **LoadCountryFlag signature.** Arguments 4-7 are integers (`mov [rsp+20h],r9d` in the prologue `12CD970`; the caller `12CEBE4..12CEBF4` stores dwords), so the hook's `int` signature is correct.

- **Null-object widgets.** `CNullEditBox` and `CNullInstantTextBox` are distinct RTTI classes, so the vtable check in `guarded_find` works for both lookups (see M4 for the test gap).
- **Memory and bounds.**
  - `core/memory.hpp` guarded reads and overflow checks;
  - count and stride bounds (variable probe, ≤4096 countries, maps, child lists, ≤64 humans);
  - `core/rtti.hpp` and `pe_image.hpp`;

- **Hook lifecycle.** Trampolines are set before any hook is enabled. Every hook body checks its enabled flag first. Both DLLs pin their module. Hook targets do not overlap between the DLLs.
- **Outside access.** No named pipe or extra thread exists in the editor: "transport" is the in-process record swap. `RNDebugRequest` accepts opcodes 1..4 only. The launcher-to-injector pipe is anonymous with an explicit handle list.
